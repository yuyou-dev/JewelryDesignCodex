# Jewelry Agent Evolution Rubric

Use this rubric before recommending a system update from a successful jewelry agent case.

## Strong Candidate

A lesson is a strong candidate when at least two of these are true:

- It explains a visible improvement in the accepted result.
- It corrects a recurring weakness in prior outputs.
- It makes a prompt or review step more precise without making it longer everywhere.
- It belongs clearly to one existing skill, reference, doc, script, or agent instruction surface.
- It can be verified with realistic future prompts.

## Weak Candidate

A lesson is weak when any of these are true:

- It depends on one user's temporary taste without broader utility.
- It locks a single gemstone, metal, camera angle, or campaign style into a global default.
- It duplicates guidance already present in another skill.
- It requires private media or context that future sessions will not have.
- It cannot be tested except by subjective preference.
- It introduces an unrelated application surface instead of improving the selected repository route.

## Disposition Guidance

- Use `apply-to-skill` for core workflow or trigger changes.
- Use `add-reference` for examples, prompt patterns, rubrics, presets, or richer domain guidance.
- Use `update-agent-instructions` for short, durable, cross-cutting behavior constraints.
- Use `update-docs` for human-facing usage, concepts, and operating guidance.
- Use `add-validator` only for mechanical rules that scripts can check reliably.
- Use `record-case-only` for inspiring but non-general visual direction.
- Use `defer` when the pattern is promising but not yet proven.

## Proposal Quality Check

Before presenting the proposal, confirm:

- The target files are named.
- The change is smaller than the lesson.
- The verification plan uses realistic jewelry tasks.
- The proposal preserves the still-image and video provider boundaries.
- The user can approve, reject, or narrow the plan without needing to inspect every repository file.
